# LifeOS — архитектура

Документ фиксирует договорённость о том, как устроено приложение.
Любая правка, которая ей противоречит, — ошибка, даже если она работает.

## 1. Термины

| Термин | Что это |
|---|---|
| **База** | одно хранилище, в нём лежат все задачи без исключения |
| **Задача** | запись в базе со своими свойствами |
| **Тип** | техническое свойство задачи: `дела` или `работа` |
| **Система** | страница «Дела» или «Работа» — те же окружения, отфильтрованные по типу |
| **Окружение** | способ показать задачи: Список, Таймлайн, Канбан, Календарь |

Систем две, и они устроены одинаково. Разница только в значении типа
и в наборе проектов. Задача переносится между системами — это смена
значения `type`, а не переезд в другое хранилище.

## 2. Идея

**Задача одна. Окружений четыре. Хранилище одно.**

Окружение не хранит задачу, не копирует её и не рисует её своим кодом.
Окружение умеет ровно три вещи:

1. **отфильтровать** — какие задачи оно показывает;
2. **разложить** — по какому свойству строится раскладка;
3. **записать** — какое свойство меняется, когда задачу перетащили.

Всё остальное — что такое задача, как она выглядит, как идёт её таймер,
как добавляются подзадачи и чек-лист — живёт в одном месте и работает
одинаково во всех окружениях и в обеих системах.

Модель взята из баз данных Notion.

## 3. Что мы копируем у Notion

Проверено по документации Notion (ноябрь 2026):

- **Вид не хранит данные.** Вид — это набор настроек поверх одной базы:
  раскладка, фильтры, сортировки, группировка, видимые свойства.
  Одни и те же записи показываются таблицей, доской, календарём и списком.
- **Доска группируется по свойству.** Перенос карточки между колонками
  записывает это свойство. Для записей с пустым значением есть
  отдельная колонка-инбокс.
- **Календарь требует свойство даты.** Перенос карточки на другой день
  записывает дату. Записи без даты не показываются — они лежат в списке
  «Без даты», откуда их перетаскивают на день.
- **Подзадачи — это связь родитель/потомок.** В списке и таймлайне они
  показываются вложенно, на доске и в календаре видны только родители.
- **Доска по статусу и доска по проекту — это два вида одной базы.**

Последнее — причина, по которой «План» и «Работа» у нас должны стать
одним окружением «канбан» с разным свойством группировки.

## 4. Свойства задачи

| Свойство | Тип | Смысл |
|---|---|---|
| `id` | строка | идентификатор |
| `name` | строка | название |
| `desc` | текст | описание, многострочное |
| `check[]` | список | чек-лист внутри задачи |
| `type` | `дела` \| `работа` | в какой системе лежит задача |
| `project` | id проекта | Эроника, Голубева — в работе; Дом, Покупки — в делах |
| `routine` | `morning` \| `evening` \| `""` | принадлежность к рутине |
| `where` | `today` \| `tomorrow` \| `backlog` \| `wait` | куда положена |
| `ord` | число | ручной порядок внутри группы |
| `at` | `ЧЧ:ММ` | время начала |
| `due` | дата | дата задачи |
| `min` | минуты | сколько времени закладываем |
| `spent`, `sessions`, `acc` | числа | факт по таймеру |
| `done`, `doneAt` | флаг, время | завершение |
| `status` | колонка канбана | не начато / в работу / в работе / жду / готово |
| `stage` | id этапа проекта | этап внутри проекта |
| `waitUntil` | дата | до какого числа «жду» |
| `archived` | флаг | убрана с доски кнопкой «Очистить» в «Готово» |
| `tm` | объект \| null | состояние таймера: `run`, `end`/`left`, `seg`, `sw` (секундомер), `rang` |
| `link`, `rel` | id, `pre`/`post` | подзадача: родитель и сторона |

У проекта тоже есть тип. Когда задача переезжает из дел в работу или
обратно, её проект сбрасывается, если он не принадлежит новому типу.

## 5. Окружения

| Окружение | Раскладывает по | Показывает | Перенос пишет | Нет свойства |
|---|---|---|---|---|
| **Список** | `ord` внутри `where` | задачи выбранной группы | `where`, `ord` | — |
| **Таймлайн** (день по часам) | `at` | у кого заполнен `at` | `at` | список «Без времени» сбоку, оттуда перетаскиванием |
| **Канбан** | `groupBy`: `where`, `status` или `project` | по фильтру системы | свойство из `groupBy`, `ord` | колонка-инбокс |
| **Календарь** (месяц) | `due` | у кого заполнена `due` | `due` | список «Без даты» |

Канбан — одно окружение с параметром `groupBy`. Доска по дням, доска по
статусам и доска по проектам — это он же с разным значением.

Каждое окружение дополнительно фильтруется по `type` той системы,
на странице которой оно открыто.

Подзадачи (`link`/`rel`): в списке и таймлайне — вложенно под родителем,
на канбане и в календаре — только родители.

## 6. Карточка

Одна функция рисует задачу в любом окружении и в любой системе: кружок
завершения, название, проект, время начала, плашка времени, «+» до/после,
иконки свойств, чек-лист, описание, состояние запущенного таймера.

Окружение может скрыть элемент карточки, но не может нарисовать свой.

## 7. Правила, чтобы не разъезжалось

1. Новое поведение задачи добавляется в модуль задачи или в карточку —
   никогда в код окружения.
2. Окружение описывается только четырьмя полями: `filter`, `groupBy`,
   `onDrop`, `missing`. Если понадобилось пятое — сначала правим документ.
3. Новое свойство задачи добавляется в таблицу раздела 4 в том же коммите.
4. Тест на единообразие проверяет, что карточка одинакова во всех
   окружениях и обеих системах. Он обязателен к прогону.

## 8. Состояние на 23.11.2026

Сделано:
- общая карточка в «Сегодня», «Плане» и рутине;
- один модуль ввода задачи `qaField`;
- `v2/index.html` — миграция всех задач в одно хранилище `lifeos.v2`,
  кнопка «Бета V2 →» в настройках v1.

Не сделано:
- в v1 три хранилища: `S.tasks`, `S.routines`, `S.work`;
- «Работа» рисует задачу своим кодом (`30-work.js`, ~1170 строк);
- блоки «Дня» (`.dblk`) рисуют задачу своим кодом;
- месячного календаря нет;
- у таймлайна нет списка «Без времени» — задача без `at` исчезает;
- окружения как абстракции нет;
- переноса между окружениями и между системами нет.

## 9. Порядок работ

1. **База.** Одно хранилище со свойствами из раздела 4, миграция старых
   данных. Сделано в `v2/index.html`, осталось добавить `type` и `desc`.
2. **Карточка.** Один модуль карточки в v2. Таймер и «Фокус» (фильтр над Списком, не свойство) уже в v2.
3. **Окружения.** Четыре штуки через `filter` / `groupBy` / `onDrop` / `missing`.
4. **Системы.** Страницы «Дела» и «Работа» поверх одних окружений.
5. **Перенос.** Между окружениями и между системами.
6. **Удаление старого кода.**

## 10. Стенд

`v2/lab.html` — страница, где все окружения показаны рядом над одним
хранилищем. Нужна, чтобы перенос задачи между окружениями проверялся
одним тестом Playwright на одном экране, а не вручную по четырём вкладкам.

## Beta 2.0 (`v2b/index.html`): что добавилось в устройстве (25.11)

*Исходники (26.11):* `v2b/src/` — `shell.html` с метками `/*@CSS*/ /*@LIB*/ /*@JS*/`, `css/00-base, 01-card, 02-envs`, `lib-qrcode.js`, `js/00-head … 28-boot` (по порядку загрузки: база и задача → карточка → таймер → … → окружения → фазы дня и окно «Дальше» → render → вкладки → карта → сценарии → boot). `build_v2b.py` склеивает их в `v2b/index.html`, который лежит в репозитории готовым (так его отдаёт Pages). Разбиение механическое: сборка совпала с прежним файлом байт в байт.

- **Сценарий = набор обычных задач** (`sc` — id сценария, `sv` — версия). Колонки сценария — версии; сумма минут считает `scenSum`.
- **Время:** `at` («ЧЧ:ММ»), `due` (дата), `min`. У пре/пост-задач (`link` + `rel`) время считает `chainSync()` внутри `save()`; метка `aa` = время авто, ручное время (без `aa`) не трогается.
- **Поповер даты и времени** (`dtp` в `panel()`): черновик в `UI.dtd`, применяется кнопкой; занятые слоты тянет из Google Calendar, только если токен уже есть.
- **Google Calendar:** прямой OAuth через Google Identity Services (`gcToken`), события создаёт `toCalendar` (`gcal` — id события).
