# LifeOS — архитектура

Документ фиксирует договорённость о том, как устроено приложение.
Любая правка, которая ей противоречит, — ошибка, даже если она работает.

## 1. Идея

**Задача одна. Окружений несколько.**

Окружение (список, календарь, канбан) не хранит задачу, не копирует её
и не рисует её своим кодом. Окружение умеет ровно три вещи:

1. **отфильтровать** — какие задачи оно показывает;
2. **разложить** — по какому свойству задачи строится раскладка;
3. **записать** — какое свойство меняется, когда задачу перетащили.

Всё остальное — что такое задача, как она выглядит, как идёт её таймер,
как добавляются подзадачи и чек-лист — живёт в одном месте и одинаково
во всех окружениях.

Модель взята из баз данных Notion.

## 2. Что мы копируем у Notion

Проверено по документации Notion (ноябрь 2026):

- **Вид не хранит данные.** Вид — это набор настроек поверх одной базы:
  раскладка, фильтры, сортировки, группировка, видимые свойства.
  Одни и те же записи показываются таблицей, доской, календарём и списком.
  Изменение настроек вида не меняет сами записи.
- **Доска группируется по свойству.** Перенос карточки между колонками
  записывает это свойство. Для записей с пустым значением есть
  отдельная колонка-инбокс.
- **Календарь требует свойство даты.** Перенос карточки на другой день
  записывает дату. Растягивание карточки задаёт диапазон.
  Записи без даты в календаре не показываются — они лежат в отдельном
  списке «Без даты», откуда их перетаскивают на день.
- **Подзадачи — это связь родитель/потомок.** В списке и таймлайне они
  показываются вложенно, на доске и в календаре по умолчанию видны
  только родители. Удаление родителя удаляет потомков.
- **Доска по статусу и доска по проекту — это два вида одной базы,**
  а не две разные сущности.

Последний пункт — ключевой. У нас «План» и «Работа» должны стать одним
окружением «канбан» с разным свойством группировки.

## 3. Модель задачи

Одно хранилище: `S.tasks`. Рутина и рабочие задачи — такие же задачи,
отличаются только значениями свойств.

| Свойство | Тип | Смысл |
|---|---|---|
| `id` | строка | идентификатор |
| `name` | строка | название |
| `note` | строка | комментарий |
| `check[]` | список | чек-лист внутри задачи |
| `project` | id проекта | связь с проектом |
| `routine` | `morning` \| `evening` \| `""` | принадлежность к рутине |
| `kind` | `work` \| `personal` | рабочая задача или личная |
| `where` | `today` \| `tomorrow` \| `backlog` \| `wait` | куда положена |
| `ord` | число | ручной порядок внутри группы |
| `at` | `ЧЧ:ММ` | время начала |
| `due` | дата | дата, к которой задача сама придёт в «Сегодня» |
| `min` | минуты | оценка времени |
| `spent`, `sessions`, `acc` | числа | факт по таймеру |
| `done`, `doneAt` | флаг, время | завершение |
| `status` | колонка доски «Работа» | не начато / в работу / в работе / жду / готово |
| `stage` | id этапа проекта | этап внутри проекта |
| `waitUntil` | дата | до какого числа «жду» |
| `link`, `rel` | id, `pre`/`post` | подзадача: родитель и сторона |

Важное следствие: **у задачи нет свойства «я из Работы» в смысле другого
кода.** `kind: "work"` — это просто значение, по которому фильтрует вид.

## 4. Окружения

| Окружение | Группирует по | Показывает | Перенос пишет | Нет свойства |
|---|---|---|---|---|
| Список («Сегодня») | `ord` внутри `where` | `where = today` | `where`, `ord` | — |
| Календарь («День») | `at` | у кого заполнен `at` | `at` | список «Без времени» сбоку, оттуда перетаскиванием |
| Канбан («План») | `where` | личные задачи | `where`, `ord` | — |
| Канбан («Работа») | `status` | `kind = work` | `status`, `ord` | колонка «Не начато» |

Канбан — одно окружение с параметром `groupBy`. «План» и «Работа»
отличаются только им и фильтром.

Подзадачи (`link`/`rel`): в списке — вложенно под родителем,
на канбане и в календаре — только родители.

## 5. Карточка

Одна функция рисует задачу в любом окружении: кружок завершения, название,
проект, время начала, плашка времени, «+» до/после, иконки свойств,
чек-лист, состояние запущенного таймера.

Окружение может скрыть элемент карточки, но не может нарисовать свой.

## 6. Правила, чтобы не разъезжалось

1. Новое поведение задачи добавляется в модуль задачи или в карточку —
   никогда в код окружения.
2. Окружение описывается только четырьмя полями: `filter`, `groupBy`,
   `onDrop`, `missing`. Если понадобилось пятое — сначала правим документ.
3. Новое свойство задачи добавляется в таблицу раздела 3 этой страницы
   в том же коммите.
4. Тест на единообразие (`test_uniform.py`) проверяет, что карточка
   одинакова во всех окружениях. Он обязателен к прогону.

## 7. Состояние на 23.11.2026

Сделано:
- общая карточка `taskCard` в «Сегодня», «Плане» и рутине;
- один модуль ввода задачи `qaField` (поле + минуты + `parseQuick`).

Не сделано:
- `S.routines.morning/evening` — отдельные массивы, не часть `S.tasks`;
- `S.work` — отдельное хранилище со своими задачами, своим перемещением
  и своим Cmd+Z (`30-work.js`, ~1170 строк);
- блоки «Дня» (`.dblk` в `20-views.js`) рисуют задачу своим кодом;
- переноса между окружениями нет;
- окружения как абстракции нет: каждый экран сам знает свои правила.

## 8. Порядок работ

1. **Модель.** Свести `S.routines` и `S.work` в `S.tasks` со свойствами
   из раздела 3. Миграция старых данных при загрузке, чтобы ничего
   не потерялось.
2. **Окружения.** Описать четыре окружения через `filter` / `groupBy` /
   `onDrop` / `missing`.
3. **Канбан.** Свести «План» и «Работа» в одно окружение с `groupBy`.
4. **Календарь.** Перевести блоки «Дня» на общую карточку, добавить
   список «Без времени» и перетаскивание из него.
5. **Перенос между окружениями.** Список → календарь → канбан.
6. **Удаление старого кода.**

## 9. Стенд

`lab.html` — страница, где все окружения показаны рядом над одним
хранилищем. Нужна для того, чтобы перенос задачи между окружениями
проверялся одним тестом Playwright на одном экране, а не вручную
по четырём вкладкам.
